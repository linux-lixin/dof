## 集成验收判据

长测检查真实 ELF 子进程及监听端口，要求核心服务、TSS、P2P、游戏频道实际 PID 在观察窗口内不变。
“五国”读取本次频道进程启动后新生成的 `Log*.init`；每次频道重启都会隔离旧日志。
健康检查还包含外部数据库可达性和近期 relay 注册，不只检查包装脚本。

测试使用与容器网卡不同的 `192.0.2.*` 通告地址，覆盖云主机 NAT 下监听/通告地址分离；
拆分服务通过不同容器 IP 连接，并验证 CORE 频道路由实际指向 GAME。
P2P 故意提前启动，CORE 延迟启动后自动注册。该拓扑模拟独立节点，未在多台物理主机上实测。

稳定窗口后注入单频道退出和数据库中断，再执行三轮停止/启动；核对数据库哨兵、管理员、RSA 配对、
PVF、公钥、hook、网关配置和自定义每日脚本，检查原始容器日志没有配置凭据。
原生日志另有 amd64/i386 探针覆盖拆分写入、无换行尾部、超长行、PID、退出码和 SIGTERM。
证据保存前脱敏；含临时密码的 state、实际 `.env`、私钥、运行数据、镜像 tar 不提交。

CentOS 基线的初始化/API/后台重启、两个实际频道进程和端口稳定 300 秒通过，
见 [CentOS 回归记录](validation/centos-baseline.json)。共享游戏资产、后台业务和默认部署未修改。

## 集成时实际发现并修复

1. 新 glibc 拒绝旧 TSS 目录式共享内存名称：加入仅作用于 i386 游戏进程的窄范围兼容库。
2. GeoIP 库加载成功但缺历史数据：内置与原镜像哈希一致的 GeoIP.dat。
3. 上游 TSS 指向不存在的远程配置服务：Ubuntu 使用本地 cfgfile 拓扑，安全通道配置保持不变。
4. 数据库中断后部分服务以状态 0 退出：修正长驻服务的 Supervisor 自动重启策略。
5. 全局 sync 在 Docker Desktop FUSE 上阻塞：改为有 30 秒上限的游戏文件同步。
6. 拍卖服务绑定公网通告地址、CORE 路由未指向 GAME：分离监听/通告地址并增加显式频道节点映射。
7. 闭源程序打印数据库密码：进程专用 launcher 过滤 stdout/stderr，保留 PID、退出码与信号语义。
8. 数据卷可能继续执行旧启动代码：增加平台标记、受管脚本哈希与用户修改冲突检查。

## 限制

- 未升级数据库、游戏协议、PVF、后台业务或登录器；第三方 DP 插件需另行验证。
- 发行包未包含远程 TSS 配置/监控服务，本地拓扑不代表远程遥测已经接入。
- 旧 OpenSSL/MySQL 客户端库是原程序 ABI 依赖；换基础系统不会消除闭源程序自身的问题。
- 性能数据为并行测试的资源快照，CentOS 还使用不同 CPU 限额，不能据此宣称性能提升。
